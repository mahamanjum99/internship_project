# KTML Internship Project

Internship project repository — Week 1: Foundation, Environment & Database Setup.

## 📋 Overview

This repository documents the setup and work completed during Week 1 of the internship, covering Python environment setup, Git version control, Oracle Database configuration, core Python library practice, and database integration.

## 🛠️ Tech Stack

- **Language:** Python 3.11
- **Database:** Oracle AI Database 26ai (Free Edition)
- **DB Connector:** `python-oracledb` (thin mode)
- **Core Libraries:** NumPy, Pandas, OpenCV, Matplotlib
- **Environment:** Python `venv`
- **IDE:** Visual Studio Code + Jupyter, Oracle SQL Developer Extension
- **Version Control:** Git + GitHub

## ✅ Week 1 Progress

### Day 1 — Environment Setup
- Python virtual environment (`venv`) created and activated
- VSCode connected to `venv` interpreter with working Jupyter kernel
- GPU/CUDA check performed (no NVIDIA GPU available — CPU-only setup)
- Core libraries installed: `numpy`, `pandas`, `opencv-python`, `matplotlib`
- Python OOP concepts refreshed (classes, inheritance, constructors)

### Day 1-2 — Git Workflow
- Repository initialized and connected to GitHub
- `.gitignore` configured to exclude `venv/` and cache files
- Regular commit and push workflow established

### Day 2-3 — Database Setup
- Oracle AI Database 26ai (Free Edition) installed locally
- Dedicated schema/user (`maham_intern`) created with appropriate privileges
- Database connection verified via SQL*Plus
- Oracle SQL Developer Extension configured in VSCode for GUI-based table
  browsing alongside terminal access

### Day 3-4 — SQL Fundamentals
- Tables created using `VARCHAR2`, `NUMBER`, `DATE`/`SYSTIMESTAMP` data types
- Auto-incrementing primary keys via `GENERATED ALWAYS AS IDENTITY`
- Foreign key relationships and `JOIN` queries implemented (`students` ↔ `courses`)
- Indexing applied for query optimization
- Connected via `python-oracledb` (thin mode — no Oracle Instant Client required)
- All queries use **bind variables** (no string-formatted SQL, per security best practice)

### Day 4-5 — Core Library Refresh
- **NumPy**: array creation, reshaping, indexing/slicing, boolean masking,
  sorting, random number generation, and statistical functions (see `Numpy_1.ipynb`)
- **Pandas**: Series/DataFrame creation, CSV handling, filtering, grouping,
  descriptive statistics, and basic visualization (see `pandas.ipynb`)
- **OpenCV**: image I/O, color space conversions, geometric transformations
  (resize/rotate/flip/crop), color-based object detection, and contour-based
  shape detection (see `opencv.ipynb`)
- Analysis results written directly to Oracle DB instead of only printing to
  console — `analysis_results` table (NumPy/Pandas/OpenCV summary stats) and
  `shape_detection_results` table (shape name, area, perimeter per detected
  contour)

### Weekend Task
- End-to-end script (`core_refresh.py`, and shape detection cell in
  `opencv.ipynb`): image load → process → write result row to DB

## 🗂️ Database Schema

Two related tables (`students`, `courses`) plus a standalone logging table
(`analysis_results`) and a shape-detection results table
(`shape_detection_results`). Full diagram in [`ERD.md`](./ERD.md) or open
[`schema.drawio`](./schema.drawio) in [draw.io](https://app.diagrams.net).

## 🚀 Setup Instructions

```bash
# Clone the repository
git clone https://github.com/mahamanjum99/internship_project.git
cd internship_project

# Create and activate virtual environment
python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # macOS/Linux

# Install dependencies
pip install -r requirements.txt
```

**Database:** Requires a local Oracle Database instance (Oracle AI Database
26ai Free or compatible) running on `localhost:1521`, with a user matching
the credentials used in the scripts (`maham_intern` / `FREEPDB1`).

## 📌 Notes

- Database credentials in scripts are for local development only and should
  not be used as-is in production.
- No NVIDIA GPU was available during setup; all work was done in a CPU-only
  environment.
- Table data itself lives inside the local Oracle Database and is not part
  of this repo — only the code that creates/queries it, plus generated
  chart images, are version controlled.
